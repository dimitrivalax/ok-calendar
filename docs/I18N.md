# Internationalisation (i18n)

**Objectif.** Définir la stack et les règles EN/FR. Voir [ADR-0009](adr/0009-i18n-fr-en.md), [SPECS.md](SPECS.md) §12.

## Décision

| | |
|--|--|
| Stack | `i18next` + `react-i18next` + `expo-localization` |
| Défaut résolu | Langue device (`en`/`fr`), sinon **`en`** |
| Fallback catalogues | **`en`** |
| Locale complète additionnelle | **`fr`** |
| Préférence | `system` (défaut) · `en` · `fr` |

## Fichiers

## Détection initiale

1. Préférence persistée (`settings.locale`) si `en`, `fr` ou `system`
2. Si `system` ou absente → langue device si `en` ou `fr`
3. Sinon **`en`** (fallback device non supporté)

La locale résolue pilote à la fois i18next et les formats `date-fns` (titres de vues, détail événement, champs date).

## Règles

- Aucune chaîne UI / a11y / corps de notif app hors catalogues
- Toute nouvelle clé : **EN + FR dans la même PR** (EN obligatoire car fallback)
- Dates : helper `dateFnsLocale()` (`enUS` / `fr`) synchronisé avec la locale résolue
- Noms mois/jours des vues : via locale active
- Contenu utilisateur (titre, description, lieu) : **non traduit**

## Settings

Sélecteur Système / EN / FR ; persistance immédiate ; re-render catalogues + dates. `Système` suit la langue du téléphone.
